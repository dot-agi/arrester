# Using Arrester

This guide covers what opens a block, how Arrester checks calls, what you and Claude see, the options, the `/arrester` command, and the diagnostics.

Works with Claude Code 2.1.296 and later.

## What opens a block

| Guard | How Arrester sees it |
| --- | --- |
| A `PreToolUse` hook outside managed settings | The `classic.PreToolUse` event returns a deny. Where the settings hook events skip installed mods (see below), the `tool.check` verdict is `deny`, names the hook `PreToolUse`, and names no rule, or the tool's error text is `PreToolUse:<Tool> hook error: [<hook>]: <reason>`, which a hook that exits with code 2 leaves. |
| A deny rule | The `tool.check` verdict is `deny` and names the rule. |
| The auto mode classifier | The `classic.PermissionDenied` event, or the error text `Permission for this action was denied by the Claude Code auto mode classifier. Reason: <reason>. If you have other tasks …`. Arrester keeps the reason only, up to `. If you have other tasks`. A denial without a classifier verdict opens no block. |
| You | The error text that starts `The user doesn't want to proceed with this tool use.` |

One blocked call opens one block, with an id such as `b1`. The block keeps the paths that the call would have touched, the strongest access to each (`destroy`, then `write`, then `read`), and a skeleton of the command with its flags. A recursive search of a glob path, such as `rg KEY /work/config/*.env`, a `find` selection, and a recursive listing, such as `ls -R` or a Glob call, give no path, because Arrester cannot know which file the guard objected to. A listing or a search that is not recursive keeps its path as a read, also a glob path: `ls /work/secrets` keeps `/work/secrets`, and `grep KEY /work/config/*.env` keeps `/work/config/*.env`. A recursive read of a regular file, such as `grep -r KEY /work/.env` or a Grep call whose `path` is that file, keeps the file as a read. A search of a folder by `grep`, `egrep`, `fgrep`, `ugrep`, `rg`, or `ag`, such as `grep -r KEY /work/secrets`, or a Grep call whose `path` is that folder, keeps the folder as a read. Arrester looks each searched path up when the block opens. Another recursive read of a folder gives no path, such as `cp -r`, `rsync`, `tar`, `zip`, or `diff -r`. A folder gives no path when it is `/`, the home folder, the session's folder, or the project folder, when it holds one of them, or when it holds a settings or hook file. So a search that names no folder, which reads the session's folder, gives none. A folder also gives no path when the search has a file filter or a depth limit, such as `grep -r --include='*.ts' KEY /work/src`, `rg --max-depth 1 KEY /work/src`, `rg --ignore-file .ignore KEY /work/src`, or a Grep call with `glob` or `type`, or when it has `--files`, `--type-list`, `--help`, or `--version`, such as `rg --files /work/src`. Such a search of a regular file still keeps the file. A folder also gives no path when the deny reason suggests another tool, such as `Use rg instead of grep` (see [Known limits](#known-limits)).

When the call has two or more paths and the deny reason names some but not all of them, the block keeps only the paths that the reason names. Arrester splits the reason into words at blanks. It cuts quotes, backticks, and brackets from the two ends of each word. Then it reads each word in two forms: one without the `.`, `,`, `;`, `:`, `!`, and `?` at its end, and one that keeps them. When the word ends with a quote or a bracket, the second form keeps only the marks inside it, so `` `secret.`, `` gives `secret` and `secret.`. A word names a path when one of its two forms is the absolute path, the spelling in the call, the path relative to the session's folder, or the file name. A word also names a path when it names a folder that holds the path, in the same forms. Arrester reads a relative word in the session's folder and `~` in the home folder. A word with `*` names a path when it matches the file name or the path as a glob. A glob path of the call, such as `config/*.env`, is named only by its own text or by a folder that holds it. For example, a hook denies `cat config/secrets.env; cat config/app.yaml` with the reason `config/secrets.env holds production credentials`. The block keeps only `config/secrets.env`, so a later Read of `config/app.yaml` passes to your guards. The block keeps every path when the reason names none or all of the paths. It also keeps every path when a word looks like a path but names no path of the call in either form. A word looks like a path when a form holds `/` or `*`, or when a form is a word of the blocked command. A file that a glob path of the call can match, such as `config/secrets.env` or `secrets.env` for `config/*.env`, counts as a word that names no path, also when it names another path of the call. So in `/w`, after a block of `cat /w/secret /w/clean`, the reason `See ../policy.md: /w/clean is protected` keeps both paths, because `../policy.md` names no path of the call. The block also keeps every path when the blocked command changes its folder: when `cd`, `pushd`, or `popd` is a word in any part of the command, also in quotes or after a backslash. Arrester reads a relative word in the session's folder, but the command reads it in the new folder. So in `/w`, after a block of `cd /w/sub && cat ../secret /secret`, the reason `../secret and /secret are protected` keeps both paths. The block also keeps every path when a word holds `**`, such as `config/**/*.env`, when the reason has more than 256 distinct words, or when the glob comparisons of its words pass their work limit. A block from your own "No" always keeps every path. The retry rule still matches the whole blocked command. See [Known limits](#known-limits).

With managed settings on the machine, or with a Team or Enterprise sign-in, the settings hook events skip installed mods. There Arrester sees a hook block in the `tool.check` verdict, which names the deciding hook, or in the error text. The block keeps the verdict's reason, or `denied` when it has none, and the error text of the same call opens no second block. Managed-settings hook denials end before Arrester runs and cannot be captured this way. Rarely, the verdict names the hook although Claude Code made the deny, and such a deny also opens a hook block: after a hook's ask, the tool's own check or a safety check can deny with no rule, and Claude Code can refuse a hook's changed input, such as one that does not fit the tool's input.

`/clear` starts a new session with a fresh record: it has no open block and no decisions, and the next block is `b1` again. Arrester keeps the record of the session that you cleared, so an in-app `/resume` of that session brings its open blocks and its decisions back, as below. `/branch` keeps the record of the session that you branch from, because the branch keeps the history that led to each block. Each open block keeps its id and its times, so it closes when it would close in that session. The decisions, the guard files, and the block count stay too, so after `b1` the next block is `b2`. The record of calls that wait for your answer in hold mode is dropped. An in-app `/resume` of a session that ended in the same process, also by `/clear`, brings back the record that the session had when it ended, without the calls that waited for your answer in hold mode. Its blocks stop calls again. Only a block whose `block_minutes` ran out meanwhile stays closed (see [Options](#options)). When a branch or a resume keeps open blocks, the transcript shows one line, such as `arrester: this session keeps open blocks b1, b2 from before the switch. /arrester clear closes them.` From then on, each session keeps its own record: `/arrester clear` in a branch does not close the blocks of the session that you branched from. Arrester keeps these records in the memory of the Claude Code process, never on disk, and writes no file. A record holds the commands, paths, and reasons of the blocks, and your decisions. The record of a session that ended stays until 32 other sessions end after it, Arrester reloads, such as after a change in `/config`, or the process ends. So a resume in a new process, such as `claude -r`, starts with no open block; see [Known limits](#known-limits).

## How a later call is checked

While at least one block is open, each tool call is analyzed before it runs. Arrester reads shell commands without running them: it follows `cd` as if it succeeds, variables set in the same command, `~` and `$HOME`, globs, comma braces such as `{a,b}`, symbolic links made in the same command, pipelines, `xargs`, `find -exec` and `-execdir`, `sh -c`, `bash -c`, `zsh -c`, `eval`, `case … esac`, arrays, and heredocs, including inside `$(…)`. It reads `env -S` strings, honors `env -C`, and removes the runner prefixes `npx`, `bunx`, `pnpm exec`, `pnpm dlx`, `pnpx`, `npm exec` without a workspace option, `yarn dlx`, `uv run`, `uv tool run`, `uvx`, `pipenv run`, `poetry run`, and `runuser -u`. It reads the code of `su` and `runuser` as shell code, except in a login form, resolves the parameter operators that the known limits below name, and walks the functions and aliases that the same command defines, except a function whose body names `return` or `exit`. Scripts and interpreter one-liners receive a best-effort scan; the known limits below apply.

Arrester judges a script by when it last changed. When a readable script changed after the oldest open block opened, or the same command writes its known text, Arrester scans it. Recognized effects count; unreadable code usually makes the call opaque. This scan has the script limits listed below. A script that changed before then is part of your setup, such as a virtual environment's `activate` or a plugin's helper: what a shell script of that age does still counts, but code in it that Arrester cannot read does not, and in an interpreter script of that age only a literal path that is a whole argument of a definite file operation counts; see [Known limits](#known-limits). A newer script that an older script runs is still checked as a newer script.

A call matches a block by one of four rules:

| Rule | A match |
| --- | --- |
| Target | Deletion matches any related blocked path. A write matches the same path for any blocked access, or an enclosing recursive write when the blocked access was a write. Reads match read blocks only. A write inside a folder whose deletion was blocked passes. A search that names no folder, such as `rg pattern` or a Grep call without `path`, reads the session's folder; see [Known limits](#known-limits). A Grep or Glob call matches no target of a block that a `Read(` deny rule opened, because Claude Code leaves the files of Read deny rules out of those searches. The rule sees only the paths that a call names: a copy or link into a folder whose entry Arrester cannot name, such as `cp /staging/* /work/`, or that cannot replace an entry there, such as `cp -n /a/secret /work/`, records a write to the folder only. A path that an MCP call names matches a read block of the path or of a folder that holds it, and a write or deletion block of the same path unless the path is a folder that exists. A block from your own "No" is never matched this way. |
| Retry | The call repeats the blocked command with changed or added flags, or in another order, or holds the one command that the block had. For guard blocks, a retry that only drops flags passes, as does a Bash call that stays in the sandbox after a blocked call that left it. Your own "No" matches only the same command text, working folder, and relevant tool arguments. |
| Guard | The call reads or changes a user or project settings file, a regular file that a configured hook names by an absolute path or by a supported relative path (see below), or Arrester's own folder; it changes an installed plugin; or it runs `claude` with `--settings`, `--bare`, `--safe-mode`, `--dangerously-skip-permissions`, `--allow-dangerously-skip-permissions`, or `--permission-mode bypassPermissions`, or runs `claude plugin disable`, `claude plugin uninstall`, or `claude plugin configure … --values-stdin`, also as `claude plugins`. These `claude` arguments count as written or through a value that Arrester resolves. Before `plugin`, Arrester skips each argument that can be an option or an option's value, so `claude --model opus plugin disable` counts. Any other nested `claude` run counts too, except a version, help, or tool command; see [Known limits](#known-limits). A search that only passes over guards, such as `grep -r` on the project, and a read of a plugin's skills do not count. A plain run or source of a guard script, such as `bash /guards/check.sh` or `. /guards/check.sh`, does not count as a read of it. A shell that starts with a printing option on its command line and runs the script counts, such as `bash -v /guards/check.sh`; see [Known limits](#known-limits). An MCP call that names a settings file, a hook file, or a path in Arrester's folder counts too. |
| Opaque | The call runs code that Arrester cannot read: a command that does not parse, such as `time ( … )`, a zsh glob qualifier in `ls *(N)`, or an array assignment before a command, as in `F=(a) cmd`, an array form that does not resolve, decoded or downloaded text piped to a shell, code or a program name whose value cannot be resolved, a program that `su -s` or `runuser -s` names when it is not a shell that Arrester reads and the call is not a login form, a deletion target that does not resolve, a read or write target that does not resolve in a call that needs the newer reading, a script that cannot be read or is too long, code nested more than three levels deep, a command that names too many paths, an over-limit definite file operand, or exhausted path-comparison work. |

The fixed settings guards are `~/.claude/settings.json` and the project’s `.claude/settings.json` and `.claude/settings.local.json`. Hook commands contribute regular files that they name, confirmed by a file lookup. Their working folders and unknown file types add no guard. Arrester expands `~`, `$HOME`, and `$CLAUDE_PROJECT_DIR` in a hook command; a hook with `args` gets only `$CLAUDE_PROJECT_DIR`, and its `command` is the program. Every absolute path counts. A relative path, a word with a slash or a leading `.`, counts in three places only: as the program of a command, after any assignments, such as `./hooks/check.sh`; as the first such path that is no option after an interpreter or a shell, such as `python3 .claude/hooks/guard.py`, unless `-c`, `-e`, or `-m` comes first; and under a `.claude/` folder, in any place. Arrester reads it in the session's folder and in the project folder when the block opens. Other relative words, such as the file in `npx prettier --config .prettierrc`, add no guard. So do a bare name, such as `python3 guard.py`, and a script found through `PATH`. A `cd` in the hook command does not count, so the path after it guards the wrong file or none. Write `python3 "$CLAUDE_PROJECT_DIR"/hooks/guard.py` to guard such a file. Quoted hook file names keep their spaces. A filename alone never makes a guard: fixtures named `managed-settings.json` or placed in `managed-settings.d` remain ordinary files unless a configured hook names them.

Arrester applies temporary prefix assignments and `env` overrides to the child command only. It does not keep a prefix assignment before `export` or another special built-in command, which some shells keep; see [Known limits](#known-limits). Child shells inherit exported variables, including when their code comes from a quoted heredoc. An assigned `HOME` stays exported until `unset` or `export -n` removes that status. Tilde paths and argumentless `cd` use the current shell’s tracked `HOME`. `env -S` resumes option parsing after splitting its string. Directory options keep their written order. The last `env -C` or `--chdir` wins, relative to that `env` invocation’s starting directory. `xargs` preserves replacement lines, default quoting, and explicit delimiters.

Consecutive assignments resolve in shell order, while command arguments use the values from before those assignments. Known `true` and `false` results, including through `eval` and pipeline negation with `!`, select the appropriate `&&`, `||`, or `if` branch. Unknown results retain both possible variable values. Scalar `+=` assignments append to tracked values. Literal `read` input binds named variables, including with `-r`, custom field separators, and heredocs. Successive reads consume successive records; separate input redirections keep separate positions. `printf -v` assigns supported literal string formats without producing output. A valid, supported assignment selects the success branch. Inactive branches and function definitions produce no effects; a call of a function walks its body, unless the body names `return` or `exit`. After the call, each variable that the body can assign is unknown, so a deletion through it is opaque; see [Known limits](#known-limits). An executed `exit` or `exec` with a command stops later commands in that shell. The replacement command still counts. A child shell’s termination leaves its parent running. Known results from shell argument code, heredocs, and literal pipelines select the parent’s conditional branch. Assignments in a piped group or background command list stay out of the parent shell. Statically inactive `while` and `until` bodies and empty `for` bodies produce no effects. `unset`, `env -u`, and `env -i` remove tracked values. `env -S` keeps globs and braces literal. An exported variable with uncertain values makes the split string opaque; a known empty value stays empty.

`xargs -J` keeps ordinary word splitting and inserts arguments at the first standalone marker. Later markers and markers inside longer arguments stay literal. `xargs -I` checks each input item separately; `-n` preserves argument batches, and `-L` preserves logical-line batches. Blank input lines do not consume a line batch. Trailing blanks continue a logical line. Explicit delimiters, including NUL, preserve empty records between delimiters. `-r` and `--no-run-if-empty` suppress empty invocations. `-E` and `--eof` stop ordinary input at the given marker; explicit delimiters disable this marker. `find -exec` and `-execdir` distinguish separate calls ending in `\;` from batches ending in `+`. Find replacements retain their relative spelling; `-execdir` uses `./` names in the selected folder. All preceding conjunctive `-name` predicates must match the same candidate name. They and `-type f` narrow the affected paths, including through shell arguments and `xargs`. `-mindepth` and `-maxdepth` limit selected entries, including through shell arguments and `xargs`. Recursive commands can still affect contents below a selected directory. A selected regular file does not imply changes to descendants. Paths embedded into executable code remain unresolved when their selection cannot be preserved. Output from `find -exec` is unknown; it is not assumed to contain selected paths. Actions such as `-delete` suppress default path output.

Find predicate arguments remain data, even when they spell actions such as `-delete` or `-exec`. In a conjunction, `-false` suppresses later actions and their output.

Shell argument code inherits pipeline and heredoc input. `printf` keeps every data argument after its format, including values beginning with a dash. Unquoted `$@` and `$*` preserve positional order, with splitting and globbing inside each argument. With no positional parameters, quoted `"$@"` adds no argument; adjacent text and explicit empty quotes remain. Literal heredoc output can supply a variable through command substitution. Heredocs retain their final newline, and here-strings add one. Command substitution removes trailing newlines. Quoted `$*` joins arguments using the first character of `IFS`, the shell’s field separator; quoted `$@` keeps arguments separate. Numeric parameters include `${10}` and later arguments. Literal `shift` counts and `set --` update positional parameters without changing `$0`. Conditional changes retain possible values at each position. If argument counts differ, later use of the argument list is opaque until a literal `set --` replaces it. Unrelated commands remain readable.

Arrester reads each piece of code as Arrester 1.1.3 read it first. Only code that 1.1.3 did not parse takes the newer reading, which adds `case` and arrays, so every call that 1.1.3 parsed gets the result of 1.1.3, apart from the rule for variables and the folder after a function call. The newer reading and that rule run only on a call of at most 10,000 characters: a longer call with a `case` or an array keeps the result of 1.1.3, which is opaque, and a longer call that runs a function that it defines is opaque too. Once a call needs the newer reading, the rest of its code takes it too. Such a call is opaque, as on 1.1.3, when it holds code that the newer reading does not follow: an array form that does not resolve, a read or a write of a file whose path does not resolve or is relative in an unknown folder, a join before the code that 1.1.3 did not parse where one side leaves a variable without a known value, a `case` with a `;&` or `;;&` end, a call of a function whose body names `return` or `exit`, or a `while` or `until` loop that reads more than one line of literal input, which Arrester walks only once. Such a call keeps the newer reading only when all its code fits the minimal profile, anywhere, also in `$( )`, in an unquoted heredoc, in `bash -c` code, and in the command that a wrapper such as `nohup` or `xargs` runs. Else it is opaque, as on 1.1.3:
- Commands: every command name is literal text, not `"$cmd"`. The only builtins are `echo`, `cd`, `true`, `false`, and `:`. Any other bash or zsh builtin makes the call opaque, such as `printf`, `test`, `[`, `[[`, `set`, `export`, `read`, `shift`, `break`, `continue`, `exit`, `return`, `kill`, `wait`, `pwd`, `declare`, `local`, `unset`, `eval`, `alias`, `source`, `.`, `command`, `exec`, `let`, or `trap`.
- Structure: `case`, `if`, `for`, `while`, `until`, `{ }` and `( )` groups, pipelines, and lists. `!`, `time`, `select`, and `coproc` make the call opaque. The call defines no function and holds no arithmetic of any form: no `(( ))`, `$(( ))`, `$[ ]`, subscript, or offset. `( ( … ) )` with a space is two subshells.
- Expansions: inside double quotes, only `"$name"`, `"${name}"`, `"${name[@]}"`, `"${name[*]}"`, `"$1"` to `"$9"`, `"$#"`, `"$?"`, `"$$"`, `"$!"`, `"$@"`, and `"$( )"` whose code fits the profile. An unquoted expansion is allowed only as the whole value of a scalar assignment, such as `KEY=$(awk …)` or `D=$HOME`. Every other expansion makes the call opaque: one without double quotes in a command word, an argument, an array element, a `for` list, a `case` word, or a redirection target, as in `cat $f`, `echo $(date)`, `F=($x)`, or `case $x in`; an assignment value with more than the expansion, such as `D=$HOME/x`; backticks; and `${name:-word}`, `${#name}`, `${name%word}`, `${!name}`, a zsh flag, `$*`, and `$0`. Write `"$f"`, `"$(date)"`, `F=("$x")`, `case "$x" in`, and `D="$HOME/x"` instead.
- Names: an unbraced `$name` is not followed by `[`, `:`, or `(`, which zsh reads as a subscript, a modifier, or a glob qualifier, as in `"$value[n]"` or `"$p:r"`. Write `"${value}[n]"`.
- Quoting: the call holds no `$'…'`, no `$"…"`, and no backslash-newline.
- Assignments: each one is `NAME=value`, `NAME=( … )`, or `NAME+=( … )`, also as a `for` name, with no `NAME+=value` and no `NAME[…]=value`. The name is not one that bash or zsh sets or uses by itself, as the two manuals list them, such as `IFS`, `PATH`, `HOME`, `CDPATH`, `LANG`, `LC_ALL`, `TERM`, `TMPDIR`, `PS4`, `HISTSIZE`, `PWD`, `_`, `LINENO`, `RANDOM`, `SECONDS`, `BASH_REMATCH`, or zsh `MATCH`, `status`, `argv`, `path`, `functions`, and `chpwd_functions`.
- Redirections: no `{name}` redirection, and no process substitution `<( )` or `>( )`.

A call that 1.1.3 parses keeps its result with code outside the profile too. A script that changed before the oldest open block, and a script that the same command writes and then runs, keep the reading of 1.1.3, so a `case` or an array in such a script does not parse.

`case … esac` parses with its patterns in parentheses or not, `|` alternatives, the `;;`, `;&`, and `;;&` ends, and new lines, also nested in loops, functions, other cases, and command substitutions. Arrester does not test the patterns. Every branch counts, as both sides of an `if` with an unknown condition do, also when the word is known, so `x=a; case "$x" in b) rm /work/d;; esac` counts the deletion. A pattern is no path and gives no effect, but the commands in the word and in the patterns run. An assignment in a branch reaches the commands after the `case`. A branch that `;&` ends also reaches the next branch, and one that `;;&` ends reaches every later branch, but such a `case` is opaque, as on 1.1.3, since the input that the first branch reads, does not reach the next one. The branches and the path where no pattern matches join as the sides of such an `if` join. A variable that one path leaves without a known value, also one with no value before the `case`, is unknown after it, so a read, a write, or a deletion through it is opaque, as in `out=/work/build; case "$m" in c) out=$(cat /work/f);; esac; rm -r "$out"`. Since 1.2.0, this holds at every join in a call that needs the newer reading, also after an `if`, a loop, or `&&`. A call that 1.1.3 parses keeps the join of 1.1.3, where such a variable keeps the values of the other paths. As after such an `if`, the output of a `case` has no known value, and a `cd` in a branch leaves the folder unknown after the `case`. A read or a write through such a value or folder makes the call opaque, as on 1.1.3, so with `/work/secret` under a read block, `p=$(case "$e" in prod) echo /work/secret;; esac); cat "$p"` and `case "$x" in a) cd /work/secret;; esac; cat ./key` are opaque. A function definition makes such a call opaque, as on 1.1.3, also in a branch, as in `case "$(uname)" in Darwin) clean() { rm -r /work/mac; };; *) clean() { rm -r /work/build; };; esac; clean`.

Array assignments parse: `name=( … )` and `name+=( … )` in a command of assignments only, and after `declare`, `local`, `typeset`, or `readonly` with a flag that holds `a` or `A`, such as `declare -a` or `local -A`. The elements expand as command arguments do when the assignment runs, so the commands in them count. Two expansions resolve, each as a whole word in double quotes: `"${name[@]}"` gives each element as its own argument, and `"${name[*]}"` joins the elements with the first character of `IFS`. The unquoted `${name[@]}` and `${name[*]}` are outside the minimal profile, so a call with them is opaque. They resolve only for an array that the call assigns one time, at its top level, with `name=( … )`, and changes nowhere. The top level is the call's own text outside a compound command, a function, a pipeline, a background job, and code after `&&`, `||`, or `!`. A change is any other assignment of the name, also with `+=`, to an element, or in a loop, a branch, a function, or a substitution, and `unset`, `read`, `mapfile`, `readarray`, `printf -v`, `getopts`, a `for` loop over the name, and `eval`, `source`, a name reference, or a command whose program is not literal text, such as `$cmd`, that can change any variable. A `read`, a `mapfile`, a `printf -v`, an `eval`, or a `source` makes such a call opaque anyway, since the minimal profile above does not hold it. An element that Arrester cannot resolve, such as `"Bearer $KEY"`, acts as the same word does outside an array: as an argument that names no file, such as the value of `curl -H`, it adds nothing, and a read, a write, or a deletion through it makes the call opaque. So with `/work/secret` under a deletion block, `F=(/work/secret); rm "${F[@]}"` stops on the target. Every other form of an array that the code assigns or declares is opaque, as on Arrester 1.1.3, which stopped every call with an array: `$name`, `${name}`, `${name[0]}`, `${#name[@]}`, `${!name[@]}`, a slice, an operator, one of the four forms inside a longer word or an assignment, an associative array, an array with a `[key]=value` element, and an array that the call changes. An array that `read -a`, `read -A`, `mapfile`, `readarray`, `set -A`, or an element assignment such as `F[0]=x` makes also counts as an array that the code assigns. A form of an array of the call is opaque also in a script that changed before the oldest open block. Any other array form that does not resolve, such as `${BASH_REMATCH[1]}`, or `"${G[@]}"` of a variable `G` that is no array, is opaque in a call that needs the newer reading. A call that 1.1.3 parses keeps the 1.1.3 result, also for an array that `declare -a`, `read -a`, or `mapfile` makes in it: an array form there, such as `${#files[@]}` or `"${PIPESTATUS[@]}"`, does not resolve, so a read or a write through it adds no effect, and a deletion through it is opaque.

Glob matching compares every path segment and preserves quoted wildcard characters. Standard character classes such as `[[:lower:]]` use ASCII (the basic 128-character set). Wildcards exclude leading dots unless the segment begins with a literal dot. Git retry identities include the resolved repository folder. For an unlink, real-path placement resolves the parent folder and preserves the final link entry.

Zsh `**/` matches zero or more directory levels within a bounded comparison. Ordinary `*` stays within one directory level. Find name predicates can match leading dots. Zsh scalar expansions stay whole and keep wildcard characters literal. Other shells split unquoted expansions on the tracked `IFS` characters. Unset `IFS` uses spaces, tabs, and newlines; empty `IFS` disables splitting. Conditional `IFS` values remain alternatives for splitting and quoted `$*` joining.

`git rm -n` and `git rm --dry-run` preview segments add no deletion or guard-retry finding. Surrounding commands, substitutions, and redirections still count. An identical preview that the user rejected still matches.

Shell syntax-check mode (`-n` or `-o noexec`) produces no effects from executing its code. Enabling `set -n` or `set -o noexec` inside noninteractive shell code suppresses subsequent commands in that shell. As in the shell, `set` reads options only up to its first word that is no option and no option name, or up to `--` or `-`. So in `set arg -n` and `set - -n`, the `-n` is a positional parameter and the commands after it count. In zsh and ksh, a bare `+` ends the options too, so in `zsh -c 'set + -n; …'` the `-n` is a positional parameter. Bash, sh, and dash skip a bare `+`. After `-o` or `+o`, a word that starts with `-` or `+` is no option name, as in bash and ksh, so in `set -eo +x noexec` the `noexec` is a positional parameter and the commands after it count. Substitutions and redirections evaluated by the outer shell still count. A shell that starts with a printing option on its command line and runs a script file reads that script file: sh, bash, zsh, dash, or ksh with `-v`, `-x`, `--verbose`, `-o verbose`, or `-o xtrace`, and zsh with `--xtrace`. Examples are `bash -v /guards/check.sh`, `sh -x /guards/check.sh`, `bash -o xtrace /guards/check.sh`, and `zsh -x /guards/check.sh`. Fish's `-v` prints its version, so it reads no script. Nothing else counts as a read for printing. Arrester does not follow `set -v`, `set -x`, `setopt`, or `shopt -o`, and a printing option before `-c` or before code on standard input reads no script. So `set -x; . /guards/check.sh` and `bash -x -c '. /guards/check.sh'` read no script, and a printed script reads none of the scripts that it sources; see [Known limits](#known-limits). GitHub issue and pull request `--body` and `--title` values, including their short forms, remain data. `--body-file` and `-F` read local files unless their value is `-` for standard input. The words after `shuf -e` or `--echo` are data, not files. Its `-o` file still counts as a write, and its `--random-source` file as a read.

A bare `-` ends option parsing in `sh`, `bash`, `dash`, `ksh`, and `zsh`; a following operand still names a script. Without one, the shell reads stdin. Fish uses `-` as its stdin script operand. These shells, but not fish, read an option that starts with `+` as its `-` form turned off, so `bash +e -x /guards/check.sh` reads the script. `+o NAME` takes NAME, as `-o NAME` does, and so does `+O NAME` in bash. When both forms of one option appear, the last one wins, so `bash -x +x /guards/check.sh` reads no script. `+c` runs code as `-c` does. After `+s`, bash reads stdin, as after `-s`. In `dash`, `zsh`, and `ksh`, the last of `-s` and `+s` wins, so after `+s` they run the script. `sh` can be bash or dash, so when the two differ, both stdin and the script count. A bare `+` ends option parsing in `zsh` and `ksh`, as a bare `-` does, so `zsh + -x /guards/check.sh` runs a script named `-x`. `sh`, `bash`, and `dash` skip a bare `+`. Unknown expansions in executable heredocs are opaque; unknown data-only heredocs stay data. A heredoc ends at the line that matches its delimiter as written, with only the quotes removed, so `<<${EOF}` ends at `${EOF}`. Any quoted part of the delimiter, as in `<<"$EOF"`, keeps the body literal. Redirections open from left to right before the command runs. Their paths keep the original directory, and output follows descriptor copies.

Interpreter scans associate path literals and access kinds with each recognized file operation. Ordinary filenames keep wildcard characters literal; recognized glob calls expand patterns. Tildes in interpreter path literals remain literal and resolve relative to the current folder. Printing a path alone adds no file effect; a file read nested inside a print call still counts. A copy call reads its source and writes its other paths. In a Python `shutil` copy, such as `shutil.copy`, the `src=` and `dst=` keywords name the source and the destination. Otherwise the source is the first argument. In other calls, such as `fs.copyFileSync`, `src = …` is an assignment, so the source stays the first argument. `fs.cpSync` reads its first argument and writes its second. In its later arguments, such as its options, only a nested file operation counts. A file operation on `Path(…)`, such as `.read_text()` or `.unlink()`, decides the access of that path, also inside another call, and also after `.resolve()`, `.absolute()`, or `.expanduser()`. A method that changes the path, such as `.with_name()` or `.joinpath()`, makes the original path count as a read, whatever follows it and whatever call is around it. When no method follows `Path(…)`, the path keeps the access of the call around it. So does a path that ends with `.resolve()`, `.absolute()`, or `.expanduser()`. When the path goes on after them, as in `.resolve().parent`, it counts as a read. When a method follows `Path(…)` directly, a path in the arguments of that method and of the methods after it, such as `'.x'` in `Path(…).with_suffix('.x')`, takes no write or deletion from the call around them. After a method that changes the path or after `.resolve()`, such a path counts as a read. A file operation, as one of those methods or inside their arguments, keeps its own access. `Path(…).open` writes when its first argument or its `mode=` value is a literal write mode. Before the scan, Arrester blanks each comment that starts a line, after any indentation, in code that python runs (`#`) and in code that node, bun, or deno runs (`//` and `/* */`); a script run directly takes its language from its `#!` line.

A re-entered check cannot call the engine. It passes through when the cached block state is empty and refuses when blocks remain or their state is unknown. Ordinary checks still read session state.

The guard and opaque rules name the newest open block that is not a "No" of yours, and they do not apply while every open block is one.

A block that a target or retry match names is renewed: its `block_minutes` start again. A guard or opaque match alone renews no block.

## Known limits

Arrester catches common retries after a block. It is not a sandbox and cannot recognize every shell rewrite.

Most of these limits apply while a block from a hook, deny rule, or auto mode classifier is open. In hold mode, `Allow once` still runs every guard. In deny mode, inspect the call and its block with `/arrester`; clear that specific block only if you intend to end its protection.

- **Pipeline failures (`pipefail`):** With `bash -o pipefail` or `set -o pipefail`, Arrester uses only the last pipeline command's result. It can miss a protected read after `||`, or falsely stop an `&&` branch that Bash would skip. Check these branches yourself and ask Claude to use explicit paths in separate calls after you approve the intended work.
- **Input inherited by command substitutions:** When `$(cat)` reads a path from the surrounding shell's heredoc, Arrester loses that input. A later read through the assigned variable can pass without an Arrester stop or warning. Ask Claude to state the path explicitly so you and the guards can check the intended read.
- **Command-substitution assignments:** Arrester loses the success or failure result of an assignment such as `p=$(true)` or `p=$(false)`. It can falsely stop a protected action after `||` or `&&` that the shell would skip. Inspect the conditional branch before choosing `Allow once` in hold mode.
- **Exit on failure (`errexit`):** With `bash -e` or `set -e`, Arrester can still check commands after a failure that would end the shell. It can falsely stop a later deletion that Bash would never run. Confirm that the failure exits the shell in that context before choosing `Allow once` in hold mode.
- **Pathname text helpers:** `basename` and `dirname` only change text, so they read no path. Their output still counts as a listing of their operands. So while `/work/secret` is under a read block, `dirname /work/secret | xargs cat` stops as a read of `/work/secret`, although it reads `/work`. Check such a pipeline before choosing `Allow once` in hold mode.
- **Paths that the deny reason does not name:** When a blocked call has two or more paths and the deny reason names some but not all of them, the block keeps only the named paths; see [What opens a block](#what-opens-a-block). After such a block, a detour to a path that the reason does not name passes without a stop or a warning. The guard still checks that path. For example, a hook denies `cat config/secrets.env; cat config/app.yaml` because `config/secrets.env holds production credentials`. Then `head config/app.yaml` passes to the hook. A word of the reason can also name a path by chance, such as `data` for a folder named `data`, and then the block keeps only the paths in that folder. Arrester finds a folder change only by the words `cd`, `pushd`, and `popd` in the command. A folder change that it does not see there still lets the block keep only the named paths. Examples are a `-C` or `--chdir` option of `env`, a `cd` inside a script that the command sources, and a program name that a variable builds. Run `/arrester` to see the paths that a block keeps.
- **Searches that name no folder:** A search with a pattern and no file or folder operand counts as a read of the session's folder: `grep`, `egrep`, `fgrep`, or `ugrep` with `-r` or `-R`; `rg` or `ag` unless a pipe, an input file, a heredoc, or a here-string gives it input, where `</dev/null` and `<&-` give none; and a Grep or Glob call without `path`. With `--files`, `--type-list`, `--help`, or `--version`, the search reads nothing. rg and ag skip hidden names, so for them Arrester counts only the entries whose path below the folder has no name that starts with a dot. It counts every entry when a flag shows hidden names: `--hidden`, `-.`, or two `-u` for rg, and `--hidden` or `-u` for ag. A search with a file filter counts as no read: rg with `-g`, `--glob`, `--iglob`, `-t`, `-T`, `--type`, `--type-not`, or `--type-add`; grep, egrep, fgrep, or ugrep with `--include`, `--exclude`, `--exclude-dir`, `--exclude-from`, `--include-dir`, `--include-from`, `--include-fs`, `--exclude-fs`, `--glob`, `--iglob`, `--file-extension`, `--file-type`, `--file-magic`, or `--ignore-files`, and ugrep also with `-O`, `-t`, `-g`, or `-M`; and ag with `-G`, `-g`, `-p`, or a long flag other than its search and output options, such as `--ignore`, `--ignore-dir`, `--file-search-regex`, or a file type such as `--js`. So with `/work/.env` under a read block, `rg -g '*.env' KEY` and `grep -r --include='*.env' KEY` in `/work` read the file without a stop or a warning. A search with a depth limit also counts as no read: rg with `-d`, `--max-depth`, or `--maxdepth`; ag with `-n`, `--norecurse`, or a `--depth` of zero or more; and ugrep with `--depth` or a digit flag such as `-2`. So with `/work/secret` under a read block, `rg --max-depth 1 KEY` in `/work` reads the file without a stop or a warning. Some other reads also pass without a stop or a warning: hidden files that a ripgrep config file or an rg flag that Arrester does not read shows; a recursive grep through an option that Arrester does not read, such as `-d recurse`; and a search by a subagent that runs in its own folder, which Arrester reads in the session's folder. Such a search can also stop falsely: rg and ag skip a hidden file below a visible folder, such as `apps/web/.env`, and a file that `.gitignore` hides, but Arrester counts both. rg or ag after a pipe from a filter that gets no input itself, such as `cat | rg pattern`, counts too. A Grep or Glob call matches no target of a block from a `Read(` deny rule, because Claude Code leaves those files out of its search. Ask Claude to name the search folder, and check searches without one yourself while a read block is open.
- **Copies into a folder:** For a copy, move, or link into a folder, such as `cp /work/staging/secret /work/` or `cp -t /work /work/staging/secret`, Arrester records a write of the entry that it makes there, `/work/secret`, beside the write to the folder. `cp --parents` and `rsync -R` join the whole source path, from the `/./` marker for rsync, and `ln -f TARGET` alone writes `./<name>`. Arrester cannot name the entry when the source's last name is a glob, as in `cp /staging/* /work/`, or comes from `find -exec {}`, from `xargs` input that it cannot know, or from a remote host, or when the source is `.` or an rsync source that ends in `/`, such as `rsync -a /staging/ /work/`. Such a copy can replace a file under a write or deletion block without a stop or a warning. Under a deletion block, a recursive copy of a folder, such as `cp -r /staging/d /work/` with `/work/d/secret` blocked, also passes, because a recursive write that contains a file matches write blocks only. Arrester records the entry also when the destination is a file and no folder, so with `/work/new/secret` blocked, `cp /a/secret /work/new` stops falsely. `-T` and `install -d` add no entry. A copy, move, or link that cannot replace an entry or changes nothing adds no entry either: `cp` or `mv` with `-n`, `--no-clobber`, `--update=none`, or `--update=none-fail` and without `-f` or `-i`; rsync with `-n`, `--dry-run`, or `--ignore-existing`; and `ln` without `-f`, `-i`, `-b`, `-F`, or `-S`. Arrester does not follow the order of these flags: a call that gives `-n` together with `-i` or `-f`, such as `cp -i -n`, still adds the entry, so with an existing `/work/secret` under a write block it stops falsely. Such a call can still make an entry that does not exist yet, so with `/work/secret` under a write block and not yet made, `cp -n /a/secret /work/` makes it without a stop or a warning. A copy of 128 or more named files into one folder passes the limit of 256 path effects, so it is opaque. Ask Claude to name the destination file, and check globbed or found copies into the folder of a protected file yourself.
- **Running or sourcing a script:** A plain run or source of a script does not count as a read of the script file. Arrester checks the commands inside the script instead. So `bash /guards/check.sh` and `. /guards/check.sh` pass without a guard stop, and a script under a read block runs without a target stop. A shell that starts with a printing option on its command line and runs a script file counts as a read of that file, so `bash -v /guards/check.sh`, `sh -x /guards/check.sh`, and `zsh -x /guards/check.sh` stop, and so do `cat /guards/check.sh` and `bash -n /guards/check.sh`. [How a later call is checked](#how-a-later-call-is-checked) lists the options. Other ways to print a script pass without a stop or a warning; see **Printing options that code sets**. Options can also come from the environment, such as `SHELLOPTS=xtrace bash /guards/check.sh` or a `BASH_ENV` file that runs `set -v`, or from the script's `#!` line. Check such calls that run or source a guard script or a protected script yourself.
- **Printing options that code sets:** A script that a shell prints after `set -x` or `set -v`, or after a printing option before `-c`, passes without a stop or a warning. Arrester reads a printing option only on the command line of a shell that runs a script file. So `set -x; . /guards/check.sh`, `bash -c 'set -v; source /guards/check.sh'`, and `bash -x -c '. /guards/check.sh'` pass. So do a printing option before code on standard input, as in `bash -x <<< '. /guards/check.sh'`, a script printed after `setopt xtrace` or `shopt -so xtrace`, and a script that a printed script sources, as when `bash -x /work/run.sh` sources `/guards/check.sh`. Check calls that turn on `-x` or `-v` before they run or source a guard script or a protected script yourself.
- **Failed folder changes:** Arrester assumes that every `cd` or `pushd` succeeds. When the folder does not exist, the shell stays where it was, but Arrester resolves later relative paths in the missing folder. In `/work`, with `/work/secret` under a read block, `cd /missing || head secret` and `cd /missing; head secret` read `/work/secret` without a stop or a warning. A write or a deletion of `secret` there passes the same way. Ask Claude to use absolute paths after a `cd` that can fail, and check relative paths in such fallbacks yourself.
- **Prefix assignments that the shell keeps:** Arrester treats an assignment written before a command, such as `p=/work/secret export p`, as temporary. Some shells keep it. Bash keeps it before `export p` or `readonly p`, and `sh`, `dash`, and `ksh` keep it before any special built-in command, such as `export`, `eval`, `set`, or `:`. Arrester then does not know the value. With `/work/secret` under a read block, `sh -c 'p=/work/secret export p; head "$p"'` reads the file without a stop or a warning. A deletion through `$p` still stops as opaque. Ask Claude to write `export p=/work/secret`, or `p=/work/secret; export p`, which Arrester follows.
- **Relative names with a colon:** Arrester treats a command operand with a colon before its first slash as a remote target, such as `host:path` or a URL, and checks no file for it. So a relative file name such as `2026-10-11:notes.txt` or `dir:x/file` gets no check as an operand. In `/work`, with `/work/2026-10-11:notes.txt` under a block, `head 2026-10-11:notes.txt`, `cp /a 2026-10-11:notes.txt`, and `rm 2026-10-11:notes.txt` pass without a stop or a warning. A redirection such as `< 2026-10-11:notes.txt`, the name with `./`, and the absolute path still stop. Ask Claude to write such names with `./` or as absolute paths, and check colon names in shell commands yourself.
- **Repeated brace groups:** Arrester counts every word that brace expansion makes before it removes repeats. A word whose braces make more than 256 words is opaque, even when every word names the same path. For example, `cat /work/` followed by nine `{s,s}` groups makes 512 words that all name `/work/sssssssss`. While a block from a hook, rule, or classifier is open, such a call stops with the reason `the call names too many paths to read`. Ask Claude to write the path without repeated brace groups, or to split the call.

- A blocked recursive search whose path has a glob, such as `rg KEY /work/config/*.env` or `grep -r KEY /work/config/*.env`, a blocked search whose path comes from `find`, and a blocked recursive listing, such as `ls -R /work/secrets` or a Glob call, record no target, so the target rule never matches their block. Grep's `glob` and Glob's `pattern` add no target. A blocked listing or search that is not recursive records its path as a read, also a glob path. So a blocked `ls /work/secrets` records `/work/secrets`, and a later `head /work/secrets/token.txt` stops. A blocked `grep TOKEN /work/config/*.env` records the glob, and a later `head /work/config/secret.env` stops. A blocked recursive read of one regular file, such as `grep -rn foo /work/src/a.ts` or a Grep call with that `path`, records the file as a read, so a later read of it another way stops. A blocked search of a folder by `grep`, `egrep`, `fgrep`, `ugrep`, `rg`, or `ag`, such as `grep -r . /work/secrets`, or a Grep call with that `path`, records the folder as a read, so a later read of the folder or of any file inside it stops, such as `cat /work/secrets/token.txt`. A blocked recursive read of a folder by another program records no folder, such as `cp -r /work/secrets /tmp/s`, `rsync -a --exclude='*.env' /work/src/ /tmp/b/`, `tar -czf /tmp/s.tgz --exclude='*.env' /work/src`, `zip -r /tmp/s.zip /work/secrets`, or `diff -r /work/src /work/old`. So after such a blocked call, a read of a file inside the folder, such as `/work/src/secret.env`, passes without a stop or a warning, also when the call would have read the file. The block still stops a retry of the blocked command. A blocked search records no folder when it has a file filter or a depth limit, the flags that **Searches that name no folder** lists, when it is rg with `--ignore-file`, `--ignore-file-case-insensitive`, or `--max-filesize`, which leave files out by an ignore file or a size limit, or when it is a Grep call with `glob` or `type`. It also records no folder when it has `--files`, `--type-list`, `--help`, or `--version`, which make it list files or print something else, such as `rg --files /work/src`. - Past a limit in the [limits table](#limits), a call is opaque. It then stops while a block from a hook, rule, or classifier is open, even when it is safe. Examples are a file operand over 4,096 characters, more than 256 distinct path effects, and a glob comparison that exhausts its work budget.
- **Session switches:** Arrester keeps the record of each session that ends in the memory of the Claude Code process, never on disk. So a resume in a new process, such as `claude -r`, `claude --resume`, or `claude --continue`, starts with no open block. So does the copy that `/fork` starts, and a conversation that `/background`, `/bg`, or `←` on an empty prompt moves to a new process. The copy's history still shows each block and its reason, but Arrester there does not stop a detour; the session that you fork from keeps its blocks. A reload of Arrester, such as a change in `/config`, forgets the sessions that ended before it. Arrester keeps the records of the last 32 sessions that ended in the process, so an in-app `/resume` of an older one starts fresh. With managed settings on the machine, or with a Team or Enterprise sign-in, the settings hook events skip installed mods, so `/branch` and an in-app `/resume` start with no open block too. Before such a switch, run `/arrester` to see the open blocks, and tell Claude what stays blocked.
- At most 50 blocks stay open. A new block past that closes the oldest one early; a transcript notice and the status name it.
- Arrester keeps the last 50 decisions. `/arrester` shows the last ten, each detail on one line of at most 600 characters. `/arrester history [1-5]` shows them ten per page, each clipped to 160 characters.
- A block keeps at most 256 flags per set and 65,536 bytes of flags in all. Past that, a retry with changed flags may not match; an identical retry still does. The transcript reports the overflow.

## Limits

| Item | Limit |
| --- | --- |
| Open blocks | 50; the oldest closes first, with a loss-of-protection notice. Status retains the latest eviction. |
| Paths kept per block | 256 distinct targets, matching the effect ceiling. Incomplete analysis is reported at capture and in `/arrester`. Status shows up to 32 abbreviated targets per block and counts the remainder. |
| Exact retry identity | A 71-byte SHA-256 digest of complete syntax-preserving input and context within serialization limits. |
| Input serialization | 64 nesting levels, 16,384 traversal entries, and 4,000,000 text-work units. Exhaustion makes the call opaque and omits its exact identity. |
| Flags kept per block and per command in it | 256 per set; 65,536 UTF-8 bytes total. Overflow is explicit and disables fuzzy retry matching for incomplete sets. |
| Command read | 100,000 characters, for a command and for each shell script; a longer one is opaque, or not counted inside an older script. |
| Script read | A regular file of at most 262,144 bytes; a longer one is opaque unless it changed before the open blocks, and a device or a pipe is not read. |
| Nesting of shell code, command substitutions, scripts, function calls, alias texts, `xargs`, and `find -exec` | 3 levels; deeper code is opaque, or not counted inside an older script. |
| Compound shell syntax | 32 nested command lists or function headers; deeper syntax is opaque. |
| Values of one word, and of one call | 256 distinct alternatives and 16,384 resolved values; equivalent alternatives of variables and substitutions are deduplicated before products and joins. Past either, the call is opaque. |
| Words from brace expansion | 256 per word, counted before repeats are removed. Past it, the call is opaque, even when every word names the same path. |
| Paths that one call touches | 256 distinct effects; access, recursion, entry removal, glob, and selection remain separate. File lists scan at most 16,384 entries and 4,000,000 characters. |
| Effect paths placed per checked call (real-path lookups) | Every retained distinct path and entry mode, up to 256 effects; eight placements in flight. Repeated placements share a call-local result. |
| Tool calls in progress whose hook deny Arrester can read | 64 at once; past it the oldest record goes. A dropped record of a call that a JSON hook or another mod denied opens no block. |
| Captured call ids kept after clear or expiry | The most recent 100; an open block also prevents duplicate capture. |
| Ended sessions whose record Arrester keeps | The last 32 in the process; an in-app `/resume` of an older one starts with no open block. |
| Expanded text | 100,000 characters per value; 4,000,000 work units per analysis for text and copies. Past a limit, the call is opaque. |
| Work of the code that 1.2.0 added | 1,500,000 units per call, across the second walk of rule A4, the newer reading, the array rule, and the minimal profile: one for each token, word character, command, copied entry, queue step, and table lookup. Past it, the call is opaque. The budget keeps that work under about 130 ms on the slowest input that the release tests found. |
| Length of a call for the code that 1.2.0 added | 10,000 characters. A longer call that needs the newer reading keeps the result of 1.1.3, which did not parse it, and a longer call that runs a function that it defines is opaque, since rule A4 would walk it a second time. |
| Path length | 4,096 characters; longer definite file operands are explicitly opaque. This is an analysis limit, not a filesystem guarantee. |
| Glob comparisons | 65,536 work units per comparison; total comparison work is capped. Exhaustion is explicit uncertainty and can stop a call while a non-user block is open. |
| Decisions kept | 50; `/arrester` shows the last 10, each detail on one line of at most 600 characters. `/arrester history [1-5]` shows ten per page, clipped to 160 characters each. |
